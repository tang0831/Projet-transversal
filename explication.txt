# Explications du Projet de Gestion d'État Civil

Ce projet est une solution multi-plateforme (Web, Mobile, Console) conçue pour centraliser et optimiser la gestion des données civiles. Il repose sur une architecture moderne utilisant des algorithmes avancés pour garantir performance et fiabilité.

## 1. Backend (Dossier `backend/`)
Le backend est développé en Python (utilisant FastAPI/Flask) et constitue le cœur du système.

### Algorithmes et Structures de Données (`backend/structures/`)
Ces fichiers implémentent des algorithmes classiques pour des tâches spécifiques :
*   **avl.py (Arbre AVL)** : Arbre binaire de recherche auto-équilibré. Utilisé pour stocker et rechercher des données (comme les IDs de citoyens) avec une complexité garantie en O(log n).
*   **boyer_moore.py** : Un algorithme de recherche de chaînes de caractères très efficace. Utilisé pour effectuer des recherches textuelles rapides dans les registres (ex: recherche d'un nom dans une base de données).
*   **knapsack.py (Problème du Sac à Dos)** : Algorithme d'optimisation. Utilisé pour prioriser la synchronisation des données ou l'allocation de ressources sous contraintes.
*   **trie.py** : Structure de données de type "préfixe". Utilisée pour l'auto-complétion et la recherche rapide par préfixes (ex: suggérer des noms de localités).
*   **union_find.py** : Gère les ensembles disjoints. Utile pour détecter des connexions entre localités ou fusionner des doublons d'enregistrements civils.

### Modèles et Données (`backend/models/`)
*   **citoyen.py, acte.py, utilisateur.py** : Définissent les structures des entités principales (Citoyens, Actes de naissance/mariage, Utilisateurs/Administrateurs).
*   **file_synchronisation.py** : Gère la logique de mise en attente des données qui doivent être synchronisées entre les clients mobiles et le serveur central.
*   **localite.py, forum.py, systeme_log.py** : Gèrent respectivement la géographie, l'espace communautaire et l'historique de toutes les opérations effectuées sur le système.

### Contrôleurs (`backend/controllers/`)
Ils contiennent la logique métier. Ils reçoivent les requêtes, appellent les modèles et les structures de données, puis renvoient les résultats.
*   **sync_controller.py** : Gère spécifiquement les flux de synchronisation des données.

---

## 2. Frontend Web (Dossier `frontend/`)
Développé avec **React** et **Vite**, c'est l'interface d'administration.
*   **App.jsx** : Point central gérant le routage et l'état global de l'application web.
*   **src/components/** : Contient les interfaces pour le tableau de bord (`Home.jsx`) et le forum de discussion (`Forum.jsx`).
*   **src/api.js** : Gère toutes les communications HTTP avec l'API backend.
*   **src/Trie.js** : Implémentation côté client de l'algorithme Trie pour des recherches instantanées sans solliciter le serveur.

---

## 3. Application Mobile (Dossier `mobile/`)
Développée avec **React Native (Expo)**, elle est destinée aux agents sur le terrain.
*   **app/** : Contient tous les écrans (Login, Citoyens, Actes, Forum, Profil).
*   **services/SyncService.js** : Composant crucial qui permet le fonctionnement hors-ligne. Il stocke les actions localement et les synchronise automatiquement dès qu'une connexion internet est détectée.
*   **services/Trie.js** : Permet une recherche rapide des citoyens directement sur l'appareil mobile.

---

## 4. Base de Données
*   **setup_db.sql** et **Etat_civil.sql** : Contiennent les scripts de création des tables et des relations (clés étrangères, contraintes) nécessaires au bon fonctionnement de l'application.

## 5. Points d'Entrée
*   **backend/app.py** ou **backend/main.py** : Lancent le serveur API.
*   **start.sh** : Script utilitaire pour démarrer rapidement les différents composants du projet.
